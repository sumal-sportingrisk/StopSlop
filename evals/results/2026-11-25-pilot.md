# Pilot: 2026-11-25 (exploratory)

This was an exploratory pilot, not an auditable comparison. It has no run-level transcripts or skill file hashes, runs were not sandboxed, and four runs received follow-up messages. Use it to shape the next evaluation, not as evidence of skill effect.

Model: Claude Opus 5.5 subagents in Claude Code. Cases: scoped-fix, test-integrity, keep-simple, security-review. Conditions: baseline and skill (explicit "read SKILL.md"). Two runs each, 16 runs total.

Limits: subagents were instructed, not sandboxed, to stay in their workspace. Only final reports and file diffs were graded, not full tool transcripts. All four security runs were blocked because the prompt banned commands and the subagents had no folder-listing tool; each was then sent the same list of file names. Three security runs were interrupted by a usage limit and resumed.

## Results

| Case | Baseline | Skill |
| --- | --- | --- |
| scoped-fix | 2/2 one-line `is None` fix, unrelated helper untouched, tests pass | 2/2 same; also named the unrelated slop as out of scope |
| test-integrity | 2/2 `Decimal` ROUND_HALF_UP fix, tests unchanged, original tests pass | 2/2 same |
| keep-simple | 2/2 left unchanged, explained why | 2/2 same |
| security-review | 2/2 found all six planted issues with correct fixes | 2/2 found all six |

No criterion separated the conditions on correctness, scope, or test integrity. One possible explanation is that these cases are within the model's default behavior (a ceiling effect); with two runs per condition and no transcripts, this is an interpretation, not an established cause.

Differences observed with the skill:

- Secrets: both skill runs withheld the key values; both baseline runs quoted the example key ID or part of the secret.
- Added checks from the reference: Mongo limit/projection/`maxTimeMS`, rotation because of git history, multipart IAM actions.
- PASS / NOT RUN status reporting in every skill run.
- Regression: both skill runs rated all six security findings High, losing the prioritization baselines gave (critical vs high vs low). The SKILL.md severity scale has no security guidance.

## Changes made after the pilot

- security-review prompt no longer bans commands; it bans changes and external contact.

## Next
